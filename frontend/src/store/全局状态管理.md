# 全局状态管理 (Store)

> 路径：`frontend/src/store/`
> **最后更新**：2026-07-16

## 简介

基于 Pinia。认证、应用主题、路由菜单、**运行时配置（settings）** 等。

## 主要 Store

| Store | 文件 | 职责 |
|-------|------|------|
| Auth | `auth.ts` | 登录态、token、角色；管理端入口跳转 |
| App | `app.ts` | 主题、语言、布局 |
| Router | `router/` | 动态菜单与路由缓存 |
| **Settings** | `settings.ts` | 从后端 app-config 加载站点/极验/实名/提现等 |

## SettingsStore（2026-07 要点）

- `loadConfig()`：`fetchAppConfig()` → 写入 `config`。
- 成功后：`setRuntimeAdminApiPath(response.data.admin_api_path)`，管理端 REST 与后端一致。
- 失败：回退 `VITE_ADMIN_API_PATH`，仍可启动。
- 计算属性：`siteName`、`geetestEnabled`、`adminApiPath` 等。

管理端 bootstrap 顺序：

```text
installPinia → settingsStore.loadConfig() → installRouter → mount
```

## Auth 与存储

- 管理端模式启用 `authStorage` session 隔离，避免与用户端 localStorage 互相覆盖。
- 管理端读 token 统一走 `authStorage`。

## 规范

- 可热变更的业务开关优先走 settings store，不要写死 env。
- 管理 API 路径不要在 store 外再写一套硬编码。
