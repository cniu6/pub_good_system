# 提现流程与余额管理

本文档记录 `fst` 项目提现流程与余额管理的实现细节，包括预扣余额机制、余额操作工具、提现审核流程等内容。

## 一、提现流程概述

### 设计原则

提现流程采用"申请时预扣余额、拒绝时退回、打款时仅对历史未预扣记录补扣"的设计，确保：

1. 用户提交提现申请时立即预扣余额，避免超额提现
2. 管理员拒绝申请时自动退回预扣余额
3. 管理员打款时仅对历史未预扣记录补扣（兼容旧数据）
4. 所有余额操作通过统一工具完成，保证原子性和日志完整性

### 实现位置

- `backend/app/services/withdraw_service.go`：提现业务逻辑
- `backend/app/models/withdraw_request.go`：提现请求数据模型
- `backend/utils/balance.go`：统一余额操作工具

## 二、提现流程详解

### 2.1 用户提交提现申请

```go
func (s *WithdrawService) Create(userID uint64, req *CreateWithdrawRequest) (*models.WithdrawRequest, error)
```

**流程步骤**：

1. 检查提现功能开关（`withdraw_enabled`）
2. 验证提现金额不低于最低限额（`withdraw_min_amount`）
3. 验证收款方式是否在允许范围内（`withdraw_account_types`）
4. 验证字段长度和必填项
5. 开启事务，锁定用户行
6. 检查用户状态和余额是否充足
7. 检查是否有待处理的提现申请
8. **预扣余额**：通过 `utils.ExecuteBalanceOpTx()` 执行余额扣减
9. 创建提现申请记录，设置 `balance_deducted = true`
10. 提交事务

**关键代码**：

```go
// 预扣余额
if _, err := utils.ExecuteBalanceOpTx(tx, &utils.BalanceReq{
    UserID: userID,
    Amount: -req.Amount,
    MemoI18n: map[string]string{
        "zhCN": "提交提现申请，系统预扣余额",
        "enUS": "Balance reserved for withdrawal request",
    },
}, utils.OpChangeAndLog); err != nil {
    // 处理错误
}

// 创建提现申请
item := &models.WithdrawRequest{
    UserID:      userID,
    Amount:      req.Amount,
    Status:      models.WithdrawStatusPending,
    BalanceDeducted: true,  // 标记已预扣
}
```

### 2.2 管理员审核提现申请

```go
func (s *WithdrawService) Review(adminID uint64, req *ReviewWithdrawRequest) error
```

**流程步骤**：

1. 验证审核状态（通过或拒绝）
2. 开启事务，锁定提现申请行
3. 检查申请状态是否为待处理
4. 检查管理员不能审核自己的申请
5. **如果拒绝且已预扣余额**：通过 `utils.ExecuteBalanceOpTx()` 退回预扣余额
6. 更新审核状态和审核备注
7. 提交事务

**关键代码**：

```go
// 拒绝时退回预扣余额
if shouldRefundReservedBalance(req.Status, item.BalanceDeducted) {
    if _, err := utils.ExecuteBalanceOpTx(tx, &utils.BalanceReq{
        UserID: item.UserID,
        Amount: item.Amount,
        MemoI18n: map[string]string{
            "zhCN": fmt.Sprintf("提现申请已拒绝，退回预扣余额-申请#%d", item.ID),
            "enUS": fmt.Sprintf("Withdrawal rejected, reserved balance released - Request#%d", item.ID),
        },
    }, utils.OpChangeAndLog); err != nil {
        return err
    }
}
```

### 2.3 管理员标记打款

```go
func (s *WithdrawService) MarkPaid(adminID uint64, req *PayWithdrawRequest) error
```

**流程步骤**：

1. 验证打款备注字段长度
2. 开启事务，锁定提现申请行
3. 检查申请状态是否为已审核通过
4. 检查管理员不能给自己的申请执行打款
5. **如果未预扣余额**：通过 `utils.ExecuteBalanceOpTx()` 补扣余额
6. 更新打款状态和打款备注
7. 提交事务

**关键代码**：

```go
// 对历史未预扣记录补扣余额
if shouldDeductBalanceOnWithdrawPay(item.BalanceDeducted) {
    if _, err := utils.ExecuteBalanceOpTx(tx, &utils.BalanceReq{
        UserID: item.UserID,
        Amount: -item.Amount,
        MemoI18n: map[string]string{
            "zhCN": fmt.Sprintf("人工提现打款-申请#%d", item.ID),
            "enUS": fmt.Sprintf("Manual withdrawal payout - Request#%d", item.ID),
        },
    }, utils.OpChangeAndLog); err != nil {
        return err
    }
}
```

## 三、统一余额操作工具

### 3.1 设计目的

统一余额操作工具 `utils.ExecuteBalanceOpTx()` 用于：

1. 保证余额变动的原子性（在事务中执行）
2. 自动记录余额变动日志
3. 支持多语言备注
4. 统一处理订单状态更新（如支付订单、提现申请）

### 3.2 核心接口

```go
func ExecuteBalanceOpTx(tx *gorm.DB, req *BalanceReq, opType BalanceOpType) (*BalanceResult, error)
```

**参数说明**：

- `tx`：数据库事务
- `req`：余额操作请求
  - `UserID`：用户ID
  - `Amount`：变动金额（正数为增加，负数为减少）
  - `MemoI18n`：多语言备注（map[string]string）
  - `OrderNo`：关联订单号（可选）
  - `TradeNo`：第三方交易号（可选）
  - `OrderStatus`：订单状态（可选，用于同步更新订单状态）
- `opType`：操作类型
  - `OpFull`：完整操作（修改余额 + 更新订单状态 + 添加日志）
  - `OpChangeAndLog`：仅修改余额 + 添加日志
  - `OpLogOnly`：仅添加日志

**返回值**：

- `BalanceResult`：操作结果
  - `BeforeMoney`：操作前余额
  - `AfterMoney`：操作后余额

### 3.3 使用示例

**支付到账**：

```go
balanceResult, err := utils.ExecuteBalanceOpTx(tx, &utils.BalanceReq{
    UserID: order.UserID,
    Amount: order.Amount,
    MemoI18n: map[string]string{
        "zhCN": fmt.Sprintf("在线充值-订单号%s", outTradeNo),
        "enUS": fmt.Sprintf("Online Recharge - Order#%s", outTradeNo),
    },
    OrderNo:     outTradeNo,
    TradeNo:     tradeNo,
    OrderStatus: models.PaymentStatusPaid,
}, utils.OpFull)
```

**提现预扣**：

```go
_, err := utils.ExecuteBalanceOpTx(tx, &utils.BalanceReq{
    UserID: userID,
    Amount: -req.Amount,
    MemoI18n: map[string]string{
        "zhCN": "提交提现申请，系统预扣余额",
        "enUS": "Balance reserved for withdrawal request",
    },
}, utils.OpChangeAndLog)
```

## 四、数据库表结构

| `review_remark` | VARCHAR(255) | 审核备注 |
| `transfer_remark` | VARCHAR(255) | 打款备注 |
| `reviewed_at` | BIGINT | 审核时间 |
| `reviewed_by` | BIGINT | 审核管理员ID |
| `paid_at` | BIGINT | 打款时间 |
| `paid_by` | BIGINT | 打款管理员ID |
| `create_time` | BIGINT | 创建时间 |
| `update_time` | BIGINT | 更新时间 |
| `delete_time` | BIGINT | 删除时间（软删除） |

## 五、运行时配置

### 5.1 提现相关配置

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `withdraw_enabled` | 提现功能开关 | `true` |
| `withdraw_min_amount` | 最低提现金额 | `10` |
| `withdraw_notify_text` | 提现提示语 | 空 |
| `withdraw_account_types` | 支持收款方式（JSON数组） | `["bank","alipay","wechat","usdt"]` |

### 5.2 配置优先级

与短信配置保持一致的设计：

- 以管理员后台 / `system_settings` / SQL 为主
- `.env` 仅作为初始化部署或数据库空值时的 fallback
- 代码通过 `services.GetGlobalWithdrawEnabled()` 等统一读取配置

## 六、安全机制

| 机制 | 说明 |
|------|------|
| **事务处理** | 所有余额操作在事务中执行，保证原子性 |
| **行级锁** | 使用 `SELECT ... FOR UPDATE` 锁定用户行和提现申请行 |
| **幂等性** | 通过 `balance_deducted` 字段标记是否已预扣，避免重复操作 |
| **余额校验** | 提现前检查余额是否充足 |
| **防重复申请** | 检查是否有待处理的提现申请 |
| **字段长度限制** | 所有文本字段都有长度限制，防止溢出攻击 |
| **管理员隔离** | 管理员不能审核/打款自己的提现申请 |

## 八、兼容性说明

### 8.1 旧数据兼容

`withdraw_requests` 表新增 `balance_deducted` 字段：

- 新数据：申请时预扣余额，设置 `balance_deducted = true`
- 旧数据：`balance_deducted` 为 `false` 或 `NULL`
- 打款时：仅对 `balance_deducted = false` 的记录补扣余额

### 8.2 迁移建议

如果系统已有旧提现数据，建议：

1. 为旧数据设置 `balance_deducted = false`
2. 打款时会自动补扣余额
3. 新申请统一走预扣流程

## 九、总结

提现流程与余额管理通过以下机制确保安全性和一致性：

1. **预扣余额机制**：申请时预扣，拒绝时退回，打款时补扣
2. **统一余额工具**：通过 `utils.ExecuteBalanceOpTx()` 保证原子性和日志完整性
3. **事务处理**：所有操作在事务中执行，使用行级锁
4. **配置优先级**：以 `system_settings` 为主，`.env` 为 fallback
5. **兼容性设计**：通过 `balance_deducted` 字段兼容旧数据
