# 实名认证接入说明

## 当前仓库状态

当前仓库中的实名认证流程，**默认仍是站内人工审核流**，并不是已经接入第三方实名核验服务。

现有核心代码位置：

- `backend/app/controllers/user/realname_controller.go`
- `backend/app/controllers/admin/realname_controller.go`
- `backend/app/services/realname_service.go`

当前流程大致如下：

1. 用户提交 `real_name`、`certificate_type`、`certificate_no`、证件正反面图片。
2. 服务层做站内参数校验与重复提交控制。
3. 后台管理员在实名管理中人工审核。
4. 如果 `realname_review_required=false`，当前实现会在站内直接标记通过，但这**不等于已经调用第三方实名接口**。

因此，管理员后台里的：

- `realname_enabled`
- `realname_review_required`
- `realname_notify_text`

目前只是在控制**站内实名流程**，并不包含第三方实名服务的 AccessKey、接口地址、区域等配置。

## 运行时配置优先级

与短信配置保持一致的设计，如果后续接入第三方实名认证，建议：

- 以管理员后台 / `system_settings` / SQL 为主
- `.env` 仅作为初始化部署或数据库空值时的 fallback

不要把实名第三方的 AccessKey、SecretKey、Region 等长期主配置写成"只能改 `.env`"。

## 推荐优先对接的官方二要素核验能力

### 阿里云实人认证：`Id2MetaVerify`

- 官方文档：`https://help.aliyun.com/zh/id-verification/information-verification/developer-reference/vatsl9lfmbwe74iv`
- OpenAPI 开发者门户：`https://next.api.aliyun.com/api/Cloudauth/2019-03-07`
- 历史 V1 Go SDK 包路径：`github.com/aliyun/alibaba-cloud-sdk-go/services/cloudauth`
- SDK 状态说明：阿里云官方 GitHub 已公告 `alibaba-cloud-sdk-go` 于 `2025-03-01` 结束支持（End-of-Support），不建议新接入继续写死 V1
- 新接入建议：优先以 OpenAPI 开发者门户生成的 Go 示例为准，再锁定具体 `alibabacloud-go` V2 模块路径
- 官方接口名：`Id2MetaVerify`
- 官方 Endpoint：
  - `cloudauth.aliyuncs.com`
  - `cloudauth.cn-beijing.aliyuncs.com`
  - `cloudauth.cn-shanghai.aliyuncs.com`

适用场景：

- 传入姓名 + 身份证号，做**身份二要素核验**。
- 更适合“姓名与身份证号是否一致”的合规校验。
- **不等于**证件 OCR、活体、视频核身，也**不等于**证件图片真实性校验。

关键请求参数：

| 参数 | 含义 | 备注 |
|------|------|------|
| `ParamType` | 参数加密方式 | 官方支持 `normal` / `md5` / `sm2` |
| `UserName` | 姓名 | `ParamType=normal` 时传明文 |
| `IdentifyNum` | 身份证号 | 官方说明仅支持二代居民身份证和港澳台居住证；`ParamType=normal` 时传明文 |

返回判定要点：

- `Code == "200"` 只表示接口调用成功。
- `Message` 仅表示接口是否异常，不代表业务核验是否一致。
- 业务核验结果要看 `ResultObject.BizCode`：
  - `1`：校验一致
  - `2`：校验不一致

接入注意事项：

- 如果后续走阿里云二要素核验，建议仅对 `certificate_type == 1`（身份证）走第三方校验。
- 护照、军官证等非身份证件类型，建议继续保留人工审核。
- 不要在日志中输出完整姓名、身份证号明文。
- 若需要满足更高合规要求，可进一步采用 `md5` 或 `sm2` 参数加密方式，而不是长期停留在 `normal`。

### 腾讯云人脸核身：`IdCardVerification`

- 官方文档：`https://cloud.tencent.com/document/product/1007/33188`
- 官方 Go SDK 包路径：`github.com/tencentcloud/tencentcloud-sdk-go/tencentcloud/faceid/v20180301`
- `pkg.go.dev` 复核页面：`https://pkg.go.dev/github.com/tencentcloud/tencentcloud-sdk-go/tencentcloud/faceid/v20180301`
- 官方接口名：`IdCardVerification`
- 官方 Endpoint：`faceid.tencentcloudapi.com`

适用场景：

- 传入姓名 + 身份证号，做**身份信息认证（二要素核验）**。
- 更适合作为站内人工审核前的机器预校验步骤。
- 同样不覆盖证件图片 OCR、活体检测、视频核验等能力。

关键请求参数：

| 参数 | 含义 | 备注 |
|------|------|------|
| `Name` | 姓名 | 明文 |
| `IdCard` | 身份证号 | 明文 |

返回判定要点：

- 官方文档示例中：
  - `Response.Result == "0"`：姓名和身份证号一致
  - `Response.Result == "-1"`：姓名和身份证号不一致
- 需要同时记录 `RequestId` 便于后续排障。
- 官方文档标注默认接口请求频率限制为 `100 次/秒`。

接入注意事项：

- 该能力同样建议仅用于身份证二要素校验，不建议直接覆盖当前所有证件类型。
- 如果后续要接腾讯云实名核身，请避免把实名核验和短信密钥复用到同一组后台字段里，建议分开配置。

## 与当前系统字段的映射关系

| 当前系统字段 | 阿里云二要素 | 腾讯云二要素 | 说明 |
|------|------|------|------|
| `RealName` | `UserName` | `Name` | 可直接映射 |
| `CertificateNo` | `IdentifyNum` | `IdCard` | 可直接映射 |
| `CertificateType` | 建议仅身份证时调用 | 建议仅身份证时调用 | 非身份证件建议继续人工审核 |
| `CertificateFront` | 不参与二要素接口 | 不参与二要素接口 | 仍可保留给后台人工复核 |
| `CertificateBack` | 不参与二要素接口 | 不参与二要素接口 | 仍可保留给后台人工复核 |
| `realname_review_required` | 建议保留 | 建议保留 | 第三方二要素通过后，是否仍需人工复核由业务决定 |

## 管理后台后续扩展建议

**以下为建议新增配置，当前仓库尚未实现。**

如果后续要把第三方实名核验真正接入管理员后台，建议单独增加一个实名配置分类，而不是复用现有短信配置字段。

并且建议运行时配置与短信保持同一设计：

- 以管理员后台 / `system_settings` / SQL 为主
- `.env` 仅作为初始化部署或数据库空值时的 fallback

不要把实名第三方的 AccessKey、SecretKey、Region 等长期主配置写成“只能改 `.env`”。

建议新增的后台键至少包括：

| 建议配置键 | 用途 |
|------|------|
| `realname_provider` | 第三方实名服务商，如 `aliyun` / `tencent` |
| `realname_access_key` | 阿里云 AccessKeyId / 腾讯云 SecretId |
| `realname_secret_key` | 阿里云 AccessKeySecret / 腾讯云 SecretKey |
| `realname_endpoint` | 自定义或覆盖官方 endpoint 时使用 |
| `realname_region` | 区域字段，主要给阿里云使用 |
| `realname_param_type` | 阿里云参数加密方式：`normal` / `md5` / `sm2` |
| `realname_auto_pass_on_match` | 二要素一致时是否自动通过 |

## 接入策略建议

推荐的落地顺序：

1. 保留当前人工审核主流程不动。
2. 在服务层增加“第三方二要素预校验”步骤。
3. 只有当：
   - 证件类型为身份证；
   - 第三方接口明确返回一致；
   - 当前业务允许自动通过；
   才考虑自动标记实名通过。
4. 对于以下情况，建议继续保留人工审核：
   - 非身份证件
   - 第三方接口超时或限流
   - 二要素结果不一致
   - 仍需核对证件图片、姓名格式、特殊地区证件等

## 安全与审计建议

- 不要记录完整身份证号、完整姓名、证件正反面原图 URL 到普通业务日志。
- 仅向前端返回必要的业务提示，不要透出第三方供应商底层错误详情。
- 建议对第三方实名请求记录：
  - 服务商
  - 接口名
  - 请求时间
  - 脱敏后的证件号
  - 结果码
  - `RequestId`
- 对超时请求不要直接重试多次，避免重复计费或放大上游限流。

## 结论

对当前仓库而言：

- **短信能力已经有第三方 Provider 实现。**
- **实名认证目前仍是站内人工审核流。**
- 如果你后续要接第三方实名认证，优先考虑：
  - 阿里云 `Id2MetaVerify`
  - 腾讯云 `IdCardVerification`

它们都适合作为“身份证二要素预校验”，但不应直接替代完整的人工实名审核流程。
