# 短信插件系统 (SMS Plugin)

本文已按 `2026-04-16` 对阿里云/腾讯云官方帮助中心正文、当前仓库代码与 `go.mod` 做二次核验。本文中如同时出现“官方 API”与“SDK 包路径”，以“官方 API 定义 + 当前项目实际实现”双重标注为准。

对于当前 `fst` 项目，短信运行时配置以管理员后台"系统设置"里的 `sms` 分类为主，底层对应 `system_settings` 表。代码上由 `backend/app/services/settings_service.go` 的 `GetSMSRuntimeConfig()` 先读取数据库配置，数据库为空时才回退到 `config.GlobalConfig`（也就是 `.env` / 环境变量加载结果）。

## 双轨说明（必读）

| 轨道 | 存哪里 | 真正用途 |
|------|--------|----------|
| **云厂商模板 Code** | `system_settings.sms_template_code` / `sms_template_code_en`（设置页 SmsTab） | 阿里云 `TemplateCode`、腾讯云 `TemplateId`；**正文在云控制台审核**，本系统不会把本地模板正文推给云厂商 |
| **本地 `sms_templates` 表** | 管理端「短信模板」页 | 主要用于 **custom** 网关渲染、本地预览与审计留档；改这里 **不等于** 改了阿里云/腾讯云模板 |

管理端已提供 `POST /api/v1/{ADMIN}/sms-send-test`（对齐邮件测试）：先校验配置，再走现有 sms 插件发验证码类测试；无真云时可走 `console` 打日志自检。

运行时配置统一通过 `services.ApplyGlobalRuntimeConfig()` 应用，已纳入：
- `frontend_url`：前端访问地址
- `backend_api_url`：后端 API 外网地址（新增）
- SMTP 相关配置（`smtp_host`、`smtp_port`、`smtp_username`、`smtp_password`、`smtp_ssl`）
- 邮件系统配置（`system_email_address`、`system_email_name`）
- 注册验证码有效期（`register_code_expire_minutes`）
- JWT 时长配置（`jwt_access_expire`、`jwt_refresh_expire`）
- 登录锁定策略（`login_max_failure`、`login_lock_duration`）
- 验证码开关（`email_verify_enabled`、`sms_verify_enabled`）
- 短信 Provider 完整配置

因此，下方出现的 `.env` 示例仅用于**初始化部署、数据库为空时兜底，或无后台配置时的 fallback 参考**，不是本项目的主配置入口。

## 服务商配置（运行时以 SQL / `system_settings` 为主）

### 阿里云 (aliyun)

若数据库 `system_settings` 中的 `sms` 分类尚未配置，可使用以下 `.env` 作为兜底：

```env
SMS_PROVIDER=aliyun
SMS_ACCESS_KEY=你的AccessKey ID
SMS_SECRET_KEY=你的AccessKey Secret
SMS_SIGN_NAME=你的短信签名
SMS_TEMPLATE_CODE=SMS_xxxxxxxx
SMS_TEMPLATE_CODE_EN=SMS_xxxxxxxx_EN
SMS_REGION=cn-hangzhou
```

`SMS_TEMPLATE_CODE_EN` 为可选项。配置后，当语言为 `en-US` 时会优先发送英文模板；未配置时回退 `SMS_TEMPLATE_CODE`。

#### 阿里云官方接口核对（SendSms）

- 官方文档：`https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms`
- 当前实现：`backend/app/plugins/sms/provider_aliyun.go`
- 官方服务地址：`dysmsapi.aliyuncs.com`
- 官方请求风格：`RPC`，官方推荐使用 `POST`
- 当前项目实际 SDK：`github.com/alibabacloud-go/dysmsapi-20170525/v5/client`

| 项目字段 | 阿里云官方字段 | 说明 |
|------|------|------|
| `SMS_ACCESS_KEY` | `AccessKeyId` | 阿里云 AccessKey ID |
| `SMS_SECRET_KEY` | `AccessKeySecret` | 阿里云 AccessKey Secret |
| `SMS_SIGN_NAME` | `SignName` | 必须使用控制台中已审核通过的短信签名 |
| `SMS_TEMPLATE_CODE` | `TemplateCode` | 必须使用已审核通过的模板 Code |
| `templateParams` | `TemplateParam` | 当前项目会序列化为 JSON 字符串传给阿里云 |
| `SMS_REGION` | `RegionId` | 为空时当前代码默认回退 `cn-hangzhou` |

当前 Provider 的成功判定与注意事项：

- 以 `resp.Body.Code == "OK"` 作为发送成功判定。
- 官方返回体还包含 `BizId` 与 `RequestId`；当前项目主要记录 `RequestId`。
- 官方手机号格式支持国内 `+/+86/0086/86` 或无前缀号码；当前项目直接传业务手机号原值。
- 阿里云官方说明国内短信接口单用户默认 QPS 为 `5000/秒`。
- 官方明确提示短信发送接口**不提供幂等能力**，业务侧不要对超时请求盲目重试。

### 腾讯云 (tencent)

若数据库 `system_settings` 中的 `sms` 分类尚未配置，可使用以下 `.env` 作为兜底：

```env
SMS_PROVIDER=tencent
SMS_ACCESS_KEY=你的SecretId
SMS_SECRET_KEY=你的SecretKey
SMS_SIGN_NAME=你的短信签名
SMS_TEMPLATE_CODE=xxxxxx
SMS_TEMPLATE_CODE_EN=yyyyyy
SMS_REGION=ap-guangzhou
SMS_SDK_APP_ID=1400xxxxxx
```

`SMS_TEMPLATE_CODE_EN` 为可选项。配置后，当语言为 `en-US` 时会优先发送英文模板 ID；未配置时回退默认模板 ID。

#### 腾讯云官方接口核对（SendSms）

- 官方文档：`https://cloud.tencent.com/document/product/382/55981`
- 当前实现：`backend/app/plugins/sms/provider_tencent.go`
- 官方请求域名：`sms.tencentcloudapi.com`
- 官方 API 版本：`2021-01-11`
- 官方示例请求方式：`POST`
- 当前项目实际 SDK：`github.com/tencentcloud/tencentcloud-sdk-go/tencentcloud/sms/v20210111`

| 项目字段 | 腾讯云官方字段 | 说明 |
|------|------|------|
| `SMS_ACCESS_KEY` | `SecretId` | 腾讯云账号密钥 ID |
| `SMS_SECRET_KEY` | `SecretKey` | 腾讯云账号密钥 Key |
| `SMS_SDK_APP_ID` | `SmsSdkAppId` | `tencent` Provider 必填 |
| `SMS_SIGN_NAME` | `SignName` | 国内短信必须填签名内容，不是签名 ID |
| `SMS_TEMPLATE_CODE` | `TemplateId` | 必须填写已审核通过的模板 ID |
| `SMS_TEMPLATE_CODE_EN` | `TemplateId` | 当前项目在 `en-US` 时优先切换英文模板 ID |
| `templateParams` | `TemplateParamSet` | 腾讯云要求按模板变量顺序传数组 |

当前 Provider 的成功判定与注意事项：

- 以 `resp.Response.SendStatusSet[0].Code == "Ok"` 作为发送成功判定。
- 官方要求手机号使用 E.164 格式，例如 `+8613800138000`；当前代码在未带 `+` 时会自动补 `+86`。
- 当前项目模板参数顺序优先读取 `__template_order`，否则按 `code,expire` 后再附加其他变量。
- 腾讯云官方文档给出的默认接口频率限制为 `3000 次/秒`。

### 自定义 HTTP POST (custom)

支持任意短信网关，只要它接受 HTTP POST 请求。

若数据库 `system_settings` 中的 `sms` 分类尚未配置，可使用以下 `.env` 作为兜底：

```env
SMS_PROVIDER=custom
SMS_ACCESS_KEY=你的API Key（作为X-Api-Key头）
SMS_SECRET_KEY=你的Secret（作为Authorization Bearer头）
SMS_ENDPOINT=https://your-sms-gateway.com/api/send
SMS_BODY_FORMAT=json
SMS_SIGN_NAME=你的短信签名
SMS_TEMPLATE_CODE=模板ID（可选）
```

`SMS_BODY_FORMAT` 支持：

- `json`: 发送 `application/json`
- `form`: 发送 `application/x-www-form-urlencoded`

Custom Provider 会发送以下格式的请求：

**JSON 格式**（`SMS_BODY_FORMAT=json`）：
```json
POST /api/send
Content-Type: application/json
Authorization: Bearer {SMS_SECRET_KEY}
X-Api-Key: {SMS_ACCESS_KEY}

{
  "phone": "13800138000",
  "content": "您的验证码是 123456，有效期 5 分钟",
  "sign": "你的签名",
  "params": {
    "code": "123456",
    "expire": "5"
  }
}
```

**表单格式**（`SMS_BODY_FORMAT=form`）：
```
POST /api/send
Content-Type: application/x-www-form-urlencoded
Authorization: Bearer {SMS_SECRET_KEY}
X-Api-Key: {SMS_ACCESS_KEY}

phone=13800138000&content=%E6%82%A8%E7%9A%84%E9%AA%8C%E8%AF%81%E7%A0%81%E6%98%AF123456&sign=%E4%BD%A0%E7%9A%84%E7%AD%BE%E5%90%8D&code=123456&expire=5
```

**成功判断**：响应为以下任一情况视为成功：
- 空响应
- 以 `success`、`ok`、`0` 开头
- 包含 `"code":0` 或 `"errcode":"0"/"ok"`

## 管理后台配置说明

管理后台“系统设置”中的 `sms` 分类与当前 Provider 的对应关系如下：

运行时优先级说明：

- `system_settings` / 管理员后台配置
- `.env` / 环境变量 fallback

- `sms_provider`：选择 `aliyun` / `tencent` / `custom` / `console`。`console` 仅建议用于本地开发或排障。
- `sms_access_key`：阿里云填 `AccessKeyId`，腾讯云填 `SecretId`，自定义网关填 `X-Api-Key`。
- `sms_secret_key`：阿里云填 `AccessKeySecret`，腾讯云填 `SecretKey`，自定义网关会作为 `Authorization: Bearer ...`。
- `sms_sign_name`：必须填写服务商控制台中**已审核通过**的签名内容。
- `sms_template_code`：中文或默认语言模板；阿里云对应 `TemplateCode`，腾讯云对应 `TemplateId`。
- `sms_template_code_en`：英文模板；当前项目仅在 `lang == en-US` 时优先使用，未配置则回退默认模板。
- `sms_region`：留空时项目会使用默认区域：阿里云 `cn-hangzhou`，腾讯云 `ap-guangzhou`。
- `sms_sdk_app_id`：仅腾讯云 Provider 使用。
- `sms_endpoint` / `sms_body_format`：仅 `custom` Provider 使用。

如果后台需要配置验证码类模板，建议保持模板变量至少包含 `code` 与 `expire`。对于腾讯云，如模板变量顺序不是默认的 `code,expire`，调用侧应显式传入 `__template_order`，否则会出现“模板参数个数或顺序不匹配”的官方错误。

## 多语言模板

内置支持的语言：`zh-CN`（中文）、`en-US`（英文）。模板管理器会根据 `lang` 参数选择内容模板；阿里云 / 腾讯云则会根据语言选择对应模板 ID。

内置模板：

| Name | 用途 | zh-CN 示例 | en-US 示例 |
|------|------|-----------|-----------|
| `register_code` | 注册验证码 | 【F.st】您的注册验证码是 {code}，{expire}分钟内有效。 | [{app_name}] Your verification code is {code}, valid for {expire} minutes. |
| `login_code` | 登录验证码 | 【F.st】您正在登录，验证码是 {code}，{expire}分钟内有效。 | [{app_name}] Your login code is {code}, valid for {expire} minutes. |
| `reset_password` | 密码重置 | 【F.st】您正在重置密码，验证码是 {code}，{expire}分钟内有效。 | [{app_name}] Your password reset code is {code}, valid for {expire} minutes. |
| `bind_phone` | 手机绑定 | 【F.st】您正在绑定手机，验证码是 {code}，{expire}分钟内有效。 | [{app_name}] Your phone binding code is {code}, valid for {expire} minutes. |

模板变量：`{code}`、`{expire}`、`{app_name}`（自动从配置读取）。

## 短信日志 (sms_logs 表)

每条短信发送都会记录日志，包括：

| 字段 | 说明 |
|------|------|
| `user_id` | 关联用户（匿名发送为 0；登录用户绑手机等应写真实 ID） |
| `phone` | 手机号（脱敏显示，如 138****8000） |
| `provider` | 服务商：`aliyun` / `tencent` / `custom` / `console` |
| `template_code` | 模板 ID |
| `template_name` | 模板名称（如 `send_code` / `bind_phone`） |
| `lang` | 语言（如 `zh-CN`） |
| `content` | 脱敏后的短信内容 |
| `status` | 状态：`1`=成功，`0`=失败 |
| `error_msg` | 错误信息（失败时） |
| `request_id` | 服务商返回的请求 ID |
| `response` | 完整响应内容 |

## 数据库表

```sql
CREATE TABLE IF NOT EXISTS sms_logs (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  phone VARCHAR(32) NOT NULL COMMENT '手机号（脱敏）',
  provider VARCHAR(32) NOT NULL COMMENT '服务商',
  template_code VARCHAR(64) NOT NULL DEFAULT '' COMMENT '模板ID',
  template_name VARCHAR(64) NOT NULL DEFAULT '' COMMENT '模板名称',
  lang VARCHAR(16) NOT NULL DEFAULT 'zh-CN' COMMENT '语言',
  content VARCHAR(512) NOT NULL DEFAULT '' COMMENT '发送内容（脱敏）',
  status TINYINT(1) NOT NULL DEFAULT 0 COMMENT '状态: 1=成功, 0=失败',
  error_msg VARCHAR(512) NOT NULL DEFAULT '' COMMENT '错误信息',
  request_id VARCHAR(128) NOT NULL DEFAULT '' COMMENT '服务商请求ID',
  response TEXT COMMENT '完整响应',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_phone (phone),
  INDEX idx_provider (provider),
  INDEX idx_status (status),
  INDEX idx_created_at (created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

## 调用结构

`backend/app/services/sms_service.go` 现在只保留统一调用入口：

- `SMSConfig`
- `SMSProvider`
- `SMSService`

具体 SDK / 网关实现全部下沉到 `backend/app/plugins/sms`，由插件在初始化时根据配置创建 Provider，并注入到 `GlobalSMSService`。

## 开发/测试

未配置任何 Provider 或 Provider 全部失败时，自动 fallback 到 `ConsoleProvider`，日志输出到控制台。

生产环境不应以 `console` 作为唯一 Provider，且必须配置真实 Provider。
