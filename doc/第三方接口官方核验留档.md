## 一、短信接口官方核验

### 1. 阿里云短信：`SendSms`

#### 官方来源

- 官方文档：`https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms`
- 错误码：`https://help.aliyun.com/zh/sms/developer-reference/api-error-codes`
- 当前仓库实际 SDK：`github.com/alibabacloud-go/dysmsapi-20170525/v5/client`

#### 已确认事实

- 官方服务地址：`dysmsapi.aliyuncs.com`
- 官方请求风格：`RPC`
- 官方推荐请求方式：`POST`
- `SignName` 必须使用**已审核通过**的短信签名
- `TemplateCode` 必须使用**已审核通过**的模板 Code
- `TemplateParam` 需要传 JSON 字符串
- 成功判定：`Code == "OK"`
- 返回体中包含：
  - `BizId`
  - `RequestId`
- 单用户默认 QPS：`5000/秒`
- 官方明确说明：**不提供幂等能力**
- 官方建议：国内短信超时时间建议设置 `>= 1 秒`

#### 当前仓库落实情况

- 当前实现文件：`backend/app/plugins/sms/provider_aliyun.go`
- 成功判定：`resp.Body.Code == "OK"`
- 默认区域回退：`cn-hangzhou`
- 当前项目记录 `RequestId`，未单独存储 `BizId`

#### 边界与风险

- 不要对超时请求做无脑重试
- 因为短信接口计费，重复重试会带来重复发送或费用风险

### 2. 腾讯云短信：`SendSms`

#### 官方来源

- 官方文档：`https://cloud.tencent.com/document/product/382/55981`
- API 概览：`https://cloud.tencent.com/document/api/382/52077`
- 当前仓库实际 SDK：`github.com/tencentcloud/tencentcloud-sdk-go/tencentcloud/sms/v20210111`

#### 已确认事实

- 官方请求域名：`sms.tencentcloudapi.com`
- 当前官方文档对应版本：`2021-01-11`
- 接口默认频率限制：`3000 次/秒`
- `SmsSdkAppId` 为关键参数
- `SignName` 在发送国内短信时必须填写**签名内容**，不是签名 ID
- `TemplateId` 必须使用已审核通过的模板 ID
- `TemplateParamSet` 的个数必须与模板变量个数一致
- 成功示例中：`SendStatusSet[*].Code == "Ok"`
- 官方手机号示例使用 E.164 格式，如 `+8618501234444`
- 失败示例明确展示模板参数个数不一致会报错

#### 当前仓库落实情况

- 当前实现文件：`backend/app/plugins/sms/provider_tencent.go`
- 成功判定：`resp.Response.SendStatusSet[0].Code == "Ok"`
- 当前项目会在手机号不带 `+` 时自动补 `+86`
- 当前项目模板参数顺序依赖 `normalizeTemplateParams` 与 `__template_order`

#### 边界与风险

- 模板变量顺序不匹配时，极易触发官方模板不匹配错误
- 当前项目默认补 `+86`，因此更适合中国大陆手机号场景

## 二、实名认证接口官方核验

### 1. 阿里云实名认证：`Id2MetaVerify`

#### 官方来源

- 官方文档：`https://help.aliyun.com/zh/id-verification/information-verification/developer-reference/vatsl9lfmbwe74iv`
- OpenAPI 开发者门户：`https://next.api.aliyun.com/api/Cloudauth/2019-03-07`
- 历史 V1 Go SDK：`https://pkg.go.dev/github.com/aliyun/alibaba-cloud-sdk-go/services/cloudauth`
- 阿里云 V1 Go SDK 状态公告：`https://github.com/aliyun/alibaba-cloud-sdk-go`

#### 已确认事实

- 官方接口名：`Id2MetaVerify`
- 官方说明：传入姓名和身份证号，返回权威数据源对二要素的校验结果
- 官方 Endpoint：
  - `cloudauth.aliyuncs.com`
  - `cloudauth.cn-beijing.aliyuncs.com`
  - `cloudauth.cn-shanghai.aliyuncs.com`
- `ParamType` 支持：
  - `normal`
  - `md5`
  - `sm2`
- `IdentifyNum` 官方说明仅支持：
  - 二代居民身份证
  - 港澳台居住证
- `Code == "200"` 只表示接口调用成功
- `Message` 仅表示接口是否异常
- 业务结果需要看 `ResultObject.BizCode`：
  - `1`：校验一致
  - `2`：校验不一致

#### SDK 核验结论

- `pkg.go.dev` 可以确认历史 V1 路径 `github.com/aliyun/alibaba-cloud-sdk-go/services/cloudauth` 中确实存在 `Id2MetaVerify` 方法。
- 但阿里云官方 GitHub 已明确公告：**V1 Go SDK 已于 2025-03-01 结束支持**。
- 因此：
  - **历史兼容/老项目参考** 可以写 V1 路径
  - **新接入方案** 不应继续把 V1 写成默认推荐
- 由于本轮成功抓取到的官方正文中，未直接给出 `Id2MetaVerify` 对应的固定新版 Go 模块名，因此当前留档采用更稳妥的写法：
  - **新接入以 OpenAPI 开发者门户生成的 Go 示例为准，再锁定 V2 模块路径**

#### 当前仓库落实情况

- 当前仓库**没有**阿里云实名认证 Provider
- 当前仓库实名认证仍是站内人工审核流程

#### 边界与风险

- 不建议把非身份证件类型直接套入二要素接口
- 即使二要素一致，也不等于证件图片真实、活体真实或 OCR 完整通过

### 2. 腾讯云实名认证：`IdCardVerification`

#### 官方来源

- 官方文档：`https://cloud.tencent.com/document/product/1007/33188`
- `pkg.go.dev`：`https://pkg.go.dev/github.com/tencentcloud/tencentcloud-sdk-go/tencentcloud/faceid/v20180301`

#### 已确认事实

- 官方请求域名：`faceid.tencentcloudapi.com`
- 官方接口名：`IdCardVerification`
- 官方说明：传入姓名和身份证号，校验两者的真实性和一致性
- 默认接口请求频率限制：`100 次/秒`
- 核心请求参数：
  - `Name`
  - `IdCard`
- 官方示例返回：
  - `Result == "0"`：姓名和身份证号一致
  - `Result == "-1"`：姓名和身份证号不一致
- 返回体包含 `RequestId`
- `pkg.go.dev` 可确认 Go 包路径：`github.com/tencentcloud/tencentcloud-sdk-go/tencentcloud/faceid/v20180301`

#### 当前仓库落实情况

- 当前仓库**没有**腾讯云实名认证 Provider
- 仅存在站内实名申请与后台审核逻辑

#### 边界与风险

- 该能力适合作为身份证二要素预校验，不等于完整的人脸核身方案
- 不建议直接覆盖护照、军官证等全部证件类型
