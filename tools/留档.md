# tools 目录留档

> **最后更新**：2026-08-09

## 简介

运维 / 诊断 / 集成验证脚本，**不挂入正式 Web 服务**。请在**项目根目录**执行。

正式启动：根 `main.go` → `backend/cmd/server` → `internal/appinit` → `internal/task`。

## 子目录

| 目录/脚本 | 说明 | 怎么跑 |
|------|------|--------|
| `backup_db.ps1` / `restore_db.ps1` | 按 `DB_DRIVER` 备份/恢复（凭据只读 env/.env） | 见 `doc/备份与恢复.md` |
| `register_admin/` | 注册管理员 | `go run ./tools/register_admin ...` |
| `reset_password/` | 重置密码 | `go run ./tools/reset_password ...` |
| `cleanup/` | 历史一次性脚本（如 trade_no 占位清理）；**勿**再跑已删的 RBAC drop 脚本 | `go run tools/cleanup/cleanup_trade_no_placeholders.go`（执行前备份） |
| `diagnose/` | 易支付诊断 | `go run tools/diagnose/diagnose_epay_query.go` |
| `email/` | 邮件模板更新脚本 | `go run tools/email/update_email_templates.go` |
| `payment_test/` | 支付相关本地集成验证 | 见目录内文件 |
| `admin_stats/` | 管理端统计回归 | 见目录内文件 |
| `normalize_collations/` | 统一 MySQL 字符集/排序规则为 utf8mb4，支持 emoji | 先预览 `go run ./tools/normalize_collations`，再执行 `go run ./tools/normalize_collations -apply` |

## 和 `*_test.go` 单元测试的区别

| 类型 | 放哪 | 原因 |
|------|------|------|
| **单元测试** `*_test.go` | 与包同目录（如 `app/services/*_test.go`） | Go 规定：同包测试必须和源码一个目录，才能 `go test ./backend/...` |
| **运维/集成脚本** | 本目录 `tools/` | 不进正式启动链路，避免和业务包混在一起 |

```bash
# 单元测试（正式包旁）
go test ./backend/app/services/ ./backend/utils/ ./backend/pkg/... -count=1

# 运维工具（项目根）
go run ./tools/register_admin -h
```

## 注意

- 读根目录 `.env`，连与主程序相同的库。
- 生产操作前先备份。
- 勿把含真实密码的命令历史提交仓库。
