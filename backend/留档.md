## 最近更新（2026-07-19 ~ 2026-07-20）

### 配置与启动

- **根目录唯一 `.env`**：`findDotEnvPath` = exe 同级 → `../.env` → cwd 向上；跳过 `frontend` 纯 VITE 与 `backend/.env`（已废弃）。参考 `.env.example`。
- **CORS 细分**：`AUTH_CORS_ENABLED` / `AUTH_CORS_ORIGINS`（认证接口）；`WS_CORS_ENABLED` / `WS_CORS_ORIGINS`（Presence WebSocket）。默认关闭，关闭时 WS 沿用全局 `CORS_ORIGINS`。
- **SMTP 出站代理**：`system_settings` 的 `smtp_proxy_*`，经 `ApplyGlobalRuntimeConfig` 覆盖运行时。

### Presence / 在线用户

- **包**：`pkg/presence` + `routes/ws.go`；管理 API `/online/*`。
- **心跳周期**：`online_report_interval_seconds`（默认 30s，公开配置）；离线容忍约 3 倍周期。
- **列表归并（2026-07-20）**：`ListOnlineUsersGrouped` 按 `user_id + auth_guard` 一行多设备；踢下线仍按会话 ID。
- **会话强退**：`POST /public/session/force-logout`（过期 token 可吊销）；JWT ignore-expiry 解析。

### 短信 / 邮件

- **双轨**：云厂商用 `sms_template_code`（system_settings）；`sms_templates` 表给 custom/预览/审计。文档见 `doc/短信插件系统.md`。
- **短信发送测试**：`POST /api/v1/{ADMIN}/sms-send-test`（对齐 `email-send-test`）；无真云可走 console。
- **日志 user_id**：登录用户绑手机/改邮/重置密码等写入真实 `user_id`（`CreateSMSLog` / `CreateEmailLogWithUser`）；匿名仍为 0。元数据键 `__user_id` 不传给云厂商模板参数。
- **短信模板 CRUD**：模型 + 管理控制器；日志聚合查询增强。

### 安全与质量补强（2026-07-20，弱 JWT 本地测试跳过）

- **Fail HTTP 状态**：`utils.Fail` 业务码落在 400–599 时直接作为真实 HTTP 状态，便于访问日志统计 4xx/5xx。
- **支付通道密钥**：管理端列表/详情掩码；更新时 `***` 不覆盖真密钥。
- **证件号**：用户端/登录响应 `MaskCertificateNo`；管理端审核可看完整号。
- **日志脱敏**：`log_sanitize` 对 password/token/sign/apikey 等字段级 `***`（不仅截断）。
- **找回密码**：重置链接不再把验证码放进 URL query；邮件正文展示 code，前端表单手输。
- **API Key**：库内存 SHA256；展示末 4 位；重新生成只返回一次明文；旧明文兼容回写哈希。
- **刷新令牌重用**：`Rotate` 前 `IsRefreshSessionActive`，失败吊销该用户会话。
- **用户 API 日志统计**：`GET /user/api-logs/stats` 仅本人。
- **生产限流软提醒**：production 且 `api_rate_limit_enabled=false` 时 Warning（不阻断）。

### 其它

- **手机国际区号 / geo**：`utils/phone.go`、`dial_codes.go`；公开 geo 接口。
- **SQLite**：方言 `DATE_FORMAT` 嵌套回退修复；临时库测试路径对齐根 `.env`。
- **迁移补洞**：`sms_templates` 旧表补 `sign_name` 等列；SQLite `verification_codes`：`email→contact` 为**加列拷贝**，旧 `email` 列保留（残留正常、设计如此，见下方说明）；聚合表在 `auto_migrate` 显式 Init。
- **用户仪表盘公告**：已接真数据（`announcement_enabled` + 最近 5 条）；见下方「站内公告」。
- **管理端用户列表**：补充 `last_seen_at` / `is_online`（会话心跳）。

### 站内公告（2026-07-20）

- **表**：`announcements`、`user_announcement_reads`（`InitAnnouncementTables`）
- **开关**：`system_settings.announcement_enabled`（公开）
- **Admin API**：`/announcements` CRUD + publish/unpublish；发布时 Presence `BroadcastJSON({type:announcement})`
- **User API**：`/user/announcements` 列表/详情/已读/未读数
- **已读**：按 `(user_id, announcement_id)`，不按浏览器
- **正文**：Markdown/HTML（管理员可信）；前端 MdEditor / MdPreview
- **Hub**：新增 `BroadcastJSON` / `BroadcastToUserJSON`

### SQLite `verification_codes.email` 残留说明（D5）

MySQL 可将 `email` 列 `CHANGE` 为 `contact`。SQLite 不支持可靠改名时，采用：

1. `ADD COLUMN contact`
2. `UPDATE ... SET contact = email`
3. **保留旧 `email` 列**

因此 SQLite 库里同时存在 `email` 与 `contact` **属于预期**，不是迁移失败。业务读写只用 `contact`。

## 目录结构（当前）

```text
backend/
├── app/                 # 业务：controllers / models / services / plugins
├── routes/              # SetupRoutes + public/user/admin/ws
├── pkg/                 # config / db / middleware / presence / pluginregistry
├── internal/
│   ├── appinit/         # 启动编排
│   ├── migrate/         # 全部自迁移（含自动任务表）
│   └── task/            # 自动任务核心
├── cmd/server/          # 进程薄壳 + 前端托管
├── utils/ · docs/
├── tests/README.md
└── 留档.md
```

`pkg` = 零件；`internal` = 开机骨架。业务 API 不进 `internal`。
