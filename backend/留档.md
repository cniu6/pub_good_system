## 最近更新（2026-07-22，代码质量清理第二轮）

### 日志保留清理重构 + SQLite 真实 Bug 修复（`app/models/log_retention.go`，新增）

- **背景**：`email_logs` / `sms_logs` / `operation_logs` / `api_access_logs` 四类日志各自实现了几乎一样的
  「全局保留最新 N 条」「按用户/收件人保留最新 N 条」+ 节流调度 + 配置读取，抽成 `log_retention.go` 通用实现，
  四个 model 文件里只留薄包装函数（导出函数名/签名不变）。
- **顺带挖出并修复了一个真实 SQLite Bug**：旧实现是「查出第 N 名那一行的时间值当 cutoff，再把这个 Go
  `time.Time` 值当参数传回 `DELETE ... WHERE time_col < ? OR (time_col = ? AND id < ?)`」。这个写法在
  SQLite（`modernc.org/sqlite` 驱动）下会**把整表删空**：驱动绑定 `time.Time` 参数时用 Go 的
  `time.Time.String()` 格式（`"2006-01-02 15:04:05 +0000 UTC"`），跟表里实际存的 ISO8601 字符串
  （`"2006-01-02T15:04:05Z"`）格式不一致，字符串比较直接错乱，导致 `email_log_max_count` /
  `sms_log_max_count` 等保留清理在 SQLite 模式下每次触发都会误删全部日志。MySQL/Postgres 原生时间类型不
  受影响。**修复**：改成 `DELETE FROM t WHERE id NOT IN (SELECT id FROM (SELECT id FROM t ORDER BY time_col
  DESC, id DESC LIMIT ?) AS keep_rows)`，完全不需要把时间值序列化后再传回去，三种驱动下语义一致（内层套一层
  派生表是为了绕开 MySQL「不能在 UPDATE/DELETE 里把目标表当子查询表」的限制）。
- 测试：`log_retention_test.go`（覆盖全局保留、按分组保留、`extraWhere` 排除匿名分组、int64/time.Time 两类时间列）。

### PostgreSQL 支持（新增，`pkg/db`）

- `DB_DRIVER=postgres` 正式可用；驱动 `github.com/jackc/pgx/v5/stdlib`（选 v5.7.6，避免把 go.mod 的 `go 1.24.5` 顶到 1.25）。
- 无 ORM（无 gorm），走 `dialect_postgres.go`（DML/DDL 方言转换）+ `pg_shim.go`（驱动层统一转换，覆盖没走 `Q()`/`Exec()` 包装的 `tx.Exec("...?...")`）；架构说明见根 `CLAUDE.md`「数据库方言兼容层」。
- `db.go` 的 `CheckTableExists/CheckColumnExists/CheckIndexExists` 新增 Postgres 分支（`information_schema` + `current_schema()`、`pg_indexes`）。
- `internal/task/run.go` 的 `MaybeRenumberRunIDsIfNearLimit`（MySQL 专属 `CREATE TABLE...LIKE`/`RENAME TABLE`）对 Postgres 同 SQLite 一样跳过，不做该边缘特性的 Postgres 实现。
- **仅做过字符串转换层单元测试**（`dialect_postgres_test.go`），本机没有 Postgres 实例做过真机验证，上生产前务必自测。

### SQLite `verification_codes.email` 残留说明（D5）

MySQL 可将 `email` 列 `CHANGE` 为 `contact`。SQLite 不支持可靠改名时，采用：

1. `ADD COLUMN contact`
2. `UPDATE ... SET contact = email`
3. **保留旧 `email` 列**

因此 SQLite 库里同时存在 `email` 与 `contact` **属于预期**，不是迁移失败。业务读写只用 `contact`。

## 目录结构（当前）

```text
backend/
├── app/                 # 业务：controllers / models / services / plugins
├── routes/              # SetupRoutes + public/user/admin/ws
├── pkg/                 # config / db / middleware / presence / pluginregistry
├── internal/
│   ├── appinit/         # 启动编排
│   ├── migrate/         # 全部自迁移（含自动任务表）
│   └── task/            # 自动任务核心
├── cmd/server/          # 进程薄壳 + 前端托管
├── utils/ · docs/
├── tests/README.md
└── 留档.md
```

`pkg` = 零件；`internal` = 开机骨架。业务 API 不进 `internal`。
