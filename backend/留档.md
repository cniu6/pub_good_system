# Backend 目录留档

> 📁 **文件位置**: `backend/留档.md`  
> **最后更新**: 2026-07-16

---

## 最近更新（2026-07-16）

- **管理端 API 前缀可配置**：根 `.env` 的 `ADMIN_API_PATH`（默认 `/admin`），路由注册为 `/api/v1{ADMIN_API_PATH}`。
- **Swagger 运行时改写**：`pkg/middleware/swagger_admin_path.go` 在返回 `doc.json` 时，把注解里的 `/api/v1/admin/*` 改成实际前缀。
- **公开 app-config**：`GET /api/v1/public/app-config` 返回 `admin_api_path`，供前端注入。
- **安全加固**：支付回调绑定校验 + 日志脱敏；代登录生产禁用/禁代登管理员/短 TTL；debug 受 `ENABLE_ADMIN_DEBUG` 控制。
- **全局配置并发**：`CloneGlobalConfig` / `UpdateGlobalConfig` / `IsAdminDebugOpsEnabled`。
- **统一入口**：程序从**项目根** `main.go` / `main_embedded.go` 启动，不再以 `backend/cmd/main.go` 为主入口。
- **【已注释禁用】电商半成品草稿**：商品/分类/商城订单不挂现网、不迁表；见下文专节。

## 电商半成品草稿（【已注释禁用】·仅留档）

> **状态：已注释禁用**。代码保留作参考，**不要当现网卖货系统用**。  
> 现网真正在用的订单是 **充值支付单** `payment_orders`（`app/services/payment_service.go`），不是草稿里的商城 `orders`。

### 卖什么（设计意图，未上线）

通用商品脚手架，类型字段：`physical` 实体 / `digital` 数字 / `service` 服务 / `subscription` 订阅；支持 C2C（有卖家）与 B2C（卖家 ID=0）、分类与库存。**没有固定垂直品类，也没有完整支付发货闭环。**

### 完成度

| 项 | 说明 |
|----|------|
| 现网入口 `main.go` | **不 import 本栈** |
| 草稿路由 | **【已注释禁用】** `internal/ginweb/index.go` |
| 草稿建表 | **【已注释禁用】** `Product/Category/Order` 已从 `appinit.AutoMigrate` 注释掉 |
| 源码 | models/services/controllers **仍保留**，文件头与函数注释标明「已注释禁用·留档」 |
| 前端商城页 | **无** |

### 文件清单（留档路径）

| 路径 | 说明 | 状态 |
|------|------|------|
| `backend/models/product.go` `order.go` `category.go` | GORM 模型 | 代码留档，**迁移已注释** |
| `backend/services/product_service.go` `order_service.go` `category_service.go` | 业务逻辑 | 代码留档，**路由未挂** |
| `backend/controllers/user|admin/*` 中商品/订单 handler | 控制器 | 代码留档，**路由已注释** |
| `backend/internal/ginweb/index.go` | 草稿路由 | **电商路由整段注释** |
| `backend/internal/appinit/index.go` | 草稿启动 | **电商表迁移注释**；本包现网不调用 |
| `backend/internal/*` `backend/plugins/*`（根下） | 草稿 GORM/鉴权/插件壳 | 现网不使用 |

### 如何恢复（以后若要做商城）

1. 取消 `internal/ginweb/index.go` 里 products/categories/orders 相关注释。  
2. 取消 `appinit.AutoMigrate` 里 Product/Category/Order。  
3. 单独入口调试草稿栈（**不要**直接混进现网 `routes.SetupRoutes`，除非做完整接入）。  
4. 前端另做商城页；支付应对齐现网 `payment` 能力，勿与充值单语义混用。

## 目录结构（当前）

```text
backend/
├── app/                         # 业务核心
│   ├── controllers/             # public / user / admin 三层
│   ├── models/                  # 数据模型与 SQL
│   ├── services/                # 业务服务（支付/设置/短信/提现等）
│   ├── plugins/                 # 插件（自动发现）
│   ├── sms/                     # 短信实现细节
│   └── 业务逻辑核心.md
├── routes/                      # API 路由总入口 SetupRoutes
│   └── API路由定义与分发规则.md
├── pkg/
│   ├── config/                  # 环境/全局配置（并发安全）
│   ├── db/                      # 数据库连接与迁移
│   ├── middleware/              # 鉴权/CORS/限流/日志/Swagger 改写
│   └── pluginregistry/          # 插件注册表
├── internal/                    # 启动编排（appinit 等）
├── utils/                       # JWT/邮件/响应等通用工具
├── docs/                        # swag 生成物（docs.go/swagger.json）
├── cmd/                         # 历史/辅助入口（主入口已迁到根目录）
├── tests/                       # 集成/专项测试
└── 留档.md                      # 本文件
```

## 启动方式

```bash
# 项目根目录（推荐）
go run ./main.go
# 或
go run .

# 开发脚本（前端 + 后端）
./dev.bat
```

配置文件：项目根目录 `.env`（参考 `.env.example`）。本地 `.env` 含密钥，**不要提交**。

## 管理端两套路径（必读）

| 配置 | 含义 | 示例 |
|------|------|------|
| `ADMIN_PATH` | 前端管理**页面**入口 | `/system-mgr` |
| `ADMIN_API_PATH` | 管理端 **REST** 在 `/api/v1` 下的前缀 | `/admin` → 完整 `/api/v1/admin` |

- 页面入口需与前端 `VITE_ADMIN_BASE_PATH` 一致后重建前端。  
- API 前缀改 `ADMIN_API_PATH` 后重启后端即可；前端通过 app-config 注入，Swagger 也会改写。

## 核心模块索引

| 模块 | 路径 | 说明 |
|------|------|------|
| 路由 | `routes/routes.go` | public/user/system/admin + 插件 |

| 用户管理 | `app/controllers/admin/user_controller.go` | 含 login-as 安全限制 |
| Debug | `app/controllers/admin/debug_controller.go` | 受 `IsAdminDebugOpsEnabled` 控制 |
