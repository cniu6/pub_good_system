# 自动任务管理器 (internal/task)

> 路径：`backend/internal/task/`  
> **最后更新**：2026-07-24

## 干什么

后台周期任务：SQL 存定义与执行记录，进程内调度，管理端可启停/立即执行/看记录。

## 必要 vs 不必要（任务开关）

| 任务 | 默认 | 判定 |
|------|------|------|
| `cleanup_sessions_codes` | 开 | **必要**：过期验证码 + 失效/过期会话清理 |
| `cleanup_expired_orders` | 开 | **必要**：超时未支付只改本地状态，不查网关 |
| `cleanup_expired_idempotency` | 开 | **必要**：幂等键过期清理 |
| `prune_auto_job_runs` / `mark_stuck_auto_jobs` | 开 | **必要**：任务自身维护 |
| `reconcile_payment_orders` | **关** | **不必要默认开**：空转浪费；永久失败已落库停扫；用户端手动刷新；handler 保留可手工跑 |

## 文件

| 文件 | 职责 |
|------|------|
| `types.go` | 常量、结构体、小工具（UID / marshal） |
| `handlers.go` | `handler_key → 函数` 表 + 业务实现 |
| `seed.go` | 默认任务预设、空表导入、过密间隔温和上调 |
| `config.go` | 全局配置读写（system_settings） |
| `definition.go` | 定义表 CRUD、启停、running/lifetime、当前运行查询 |
| `run.go` | 执行记录 CRUD、修剪、清理、keep、uid 修复、id 重编号 |
| `stuck.go` | 卡住（孤儿 running）巡检 |
| `overview.go` | 管理端总览卡片 |
| `runtime.go` | `Start`、内存缓存、tick、`Trigger` |
| `runtime_test.go` | cron / 调度判定 / 预设与 handler 对齐等单测 |

## 表

- `auto_job_definitions`：任务定义；`lifetime_*` 用 `DECIMAL(30,0)` 累计终身次数
- `auto_job_runs`：执行记录；条数有上限（默认 1 万），成功记录可自动修剪

## 字段说明（易误解）

- **`max_concurrency`**：表字段保留，写入强制为 `1`；实际并发靠进程内互斥，不按该值做多并发
- **`params_json`**：预留，管理端可编辑；**当前内置 handler 均未读取**

## 运行要点

1. **空跑不落库**：调度成功且 `HandlerResult.Quiet=true`（如巡检 0 条）只更新定义表 lifetime/last_*，不写 `auto_job_runs`
2. **失败 / 超时 / 手动 / 有实质工作**：照常写执行记录
3. **「当前运行」看定义表**：正常路径是跑完才 `INSERT` runs，因此 `running_count` /「当前运行」Tab 以 `auto_job_definitions.last_status=running` 为准
4. **卡住巡检只扫定义表**：`mark_stuck_auto_jobs` 只把超时仍 `last_status=running` 的定义标为 timeout（runs 表不会有中间态 running）
5. **RetainErrors**：自动修剪先删旧成功；若仍超上限且关闭「保留错误」，再删旧 failed/timeout（`keep_forever=0`）
6. **id 逼近上限**：`MaybeRenumberRunIDsIfNearLimit`（水位 `MaxInt64-100万`）把当前行按时间重编号为 `1..N`，自增从 `N+1` 继续；与 `InsertRun` 同锁，避免换表写丢
7. **不能**「保留超大旧 id 的同时让新行从 1 起」——InnoDB 自增不能小于 `MAX(id)+1`
8. **panic 兜底**：handler 与调度派发 goroutine 均 `recover`，转成失败日志/错误，避免拖垮进程
9. **超时不提前放锁**：`Trigger` 判超时后仍等后台 handler 真正结束再 `Unlock`，同一 `job_code` 不会并发重入
10. **run_uid**：标准 UUID（36 字符），对齐表字段 `CHAR(36)`；修剪任务会顺带修复历史坏 uid
11. **卡住巡检**：只标「本进程已无锁」的孤儿 running；阈值 = max(全局卡住秒, 任务 timeout, 60)，避免误杀与重复计数
12. **handler 响应取消**：多步骤任务在步骤间检查 `ctx.Err()`，超时后不再开下一步

## 默认任务

- `prune_auto_job_runs`（1h）
- `mark_stuck_auto_jobs`（180s）
- `cleanup_expired_idempotency`（1h）
- `cleanup_expired_orders`（120s）
- `cleanup_sessions_codes`（600s）
- `reconcile_payment_orders`（存在但默认 **Enabled=false**；启动补丁会关掉仍开启的旧库配置）

新任务：在 `handlers.go` 加一行 map + 函数，并在 `seed.go` 加预设。

## 测试

```bash
go test ./backend/internal/task/ -count=1
```

单测不连库，覆盖 cron、调度防抖、running 跳过、预设 handler 是否齐全。

## 管理入口

- API：`/api/v1/{ADMIN}/auto-jobs/*`（含 `GET /running`）
- 前端：系统设置 → 自动任务管理器
