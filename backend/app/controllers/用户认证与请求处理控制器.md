# 用户认证与请求处理控制器 (Controllers)

> 路径：`backend/app/controllers/`  
> **最后更新**：2026-07-16

## 简介

控制器接收 HTTP、校验参数、调用 services、返回统一响应。按 **public / user / admin** 分包。

## 目录

```text
controllers/
├── public/     # 登录注册、app-config、支付回调
├── user/       # 资料、用户支付、实名、提现
├── admin/      # 仪表盘、用户、设置、支付、日志、debug…
└── system…     # 系统状态等（以 routes 实际注册为准）
```

## 分层与权限

| 层 | 鉴权 | 示例 |
|----|------|------|
| public | 无 | login、app-config、payment notify/return |
| user | user 或 admin token | profile、充值下单、提现申请 |
| admin | admin + AdminOnly | 用户 CRUD、补单、设置 |

管理端 URL 前缀由路由层 `ADMIN_API_PATH` 决定，控制器内相对路径注册到 `adminGroup`。

## 高危接口（2026-07）

- **LoginToUser（代登录）**：生产禁止；禁止代登管理员；目标须启用；短 TTL；安全审计日志。
- **Debug / pprof / 重启 / 手动任务**：`IsAdminDebugOpsEnabled()`，生产永远关。
- **支付回调**：参数日志脱敏；入账前服务层绑定校验。

## Swagger 注解

仍可写 `@Router /api/v1/admin/...`。自定义 `ADMIN_API_PATH` 时由中间件改写 doc.json。

## 规范

- 业务逻辑下沉 services，控制器保持薄。
- 失败统一 `utils.Fail`，成功 `utils.Success`。
