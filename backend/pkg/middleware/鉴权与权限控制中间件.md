# 鉴权与权限控制中间件 (Middleware)

> 路径：`backend/pkg/middleware/`  
> **最后更新**：2026-08-09

## 简介

拦截 HTTP 请求，处理鉴权、跨域、限流、操作/访问日志、Scalar 管理端路径改写等横切逻辑。

**两套凭证**：`Authorization: Bearer` = 登录 JWT；`X-Api-Key` = 程序调用密钥。API Key 不能打登录接口、不能打管理端写接口。必要设计与勿误修清单见 [backend/留档.md](../../留档.md)。

## 文件一览

| 文件 | 作用 |
|------|------|
| `auth.go` | JWT 校验、`AuthMiddlewareForGuard`、注入用户信息 |

| `logger.go` | 请求日志（可跳过 scalar 等路径） |
| `operation_log.go` | 管理操作审计日志 |

## 日志职责与记录边界

### API 接口日志

`APIAccessLogMiddleware` 是全局中间件：启用 `api_access_log_enabled` 后，记录所有 `/api/*` 请求；非 API 路径和 pprof 路径不记录。

记录项包括：请求 ID、用户与鉴权方式、场景、方法、路径、状态码、耗时、IP、请求头、查询参数、请求体和响应体。

- 请求头、查询参数、请求体、响应体按当前策略**原样入库，不做敏感字段脱敏**。
- 单个请求/响应体上限为 64KB、请求头总内容上限为 8KB；二进制与过大内容只记录说明文字。
- 因此该日志可能包含密码、Token、Cookie、API Key 等凭证；仅应向可信管理员开放，并按 `api_log_max_count` 设置较短保留量。

适合记录：接口调用排障、第三方回调核对、请求参数与响应结果比对、鉴权问题排查。

不应依赖它记录：WebSocket 帧内容、SSE 长连接的完整消息流、静态资源、健康检查；这些请求不属于普通 API 调用或内容不适合完整入库。

### 操作日志

`SimpleLogMiddleware` 不是全局中间件，只有显式挂载到路由组才会记录；少数高危功能也可由控制器调用 `models.CreateOperationLog` 单独写审计。

记录项包括：操作者、模块、动作、方法、路径、IP、User-Agent、处理函数、状态码、耗时，以及请求/响应内容。

- 请求/响应中的密码、Token、API Key、验证码、证件号、银行卡、手机号等字段会替换为 `***`。
- 用户中心获取 API Key（`GET /api/v1/user/apikey`）当前未挂操作日志，故不会生成操作日志。
- 后续若要审计“查看/重置 API Key”，应单独写一条只含操作者、IP、时间、路径和密钥末四位的记录，禁止把完整密钥写进操作日志。

必须优先记录：创建、更新、删除、审核、提现/支付、余额或积分调整、权限与系统配置变更、账号停用/重置、管理员代登录、数据库执行、终端执行等会改变状态或影响安全边界的动作。

默认不必记录：健康检查、静态资源、仪表盘轮询、列表/详情等普通只读查询、Presence 心跳、WebSocket/SSE 通讯。若某模块把整组路由挂到 `SimpleLogMiddleware`，其中的只读请求也会被记录；新增路由时应按实际审计价值决定是否拆分。

## 鉴权

- `AuthMiddlewareForGuard("user", "admin")`：用户接口，user 或 admin token 均可。
- `AuthMiddlewareForGuard("admin")` + `AdminOnly()`：管理端，必须管理员。
- 校验失败必须 `c.Abort()`，统一业务错误响应。

## Scalar 管理端路径改写

```text
GET /scalar/*any
  → ScalarAdminPathRewriteMiddleware
  → gin-scalar
```

- 仅当请求路径以 `openapi.json` 结尾且 `ADMIN_API_PATH != /admin` 时拦截并返回改写后的 JSON。
- 注解仍写死 `@Router /api/v1/admin/...`，避免全量改注释；运行时与真实路由对齐。
- 匹配规则：精确 `/api/v1/admin` 或前缀 `/api/v1/admin/`，避免误伤 `administrator` 类路径。

## 规范

- 注入上下文的键名全局统一。
- 管理端高危能力（debug）在控制器层再用 `IsAdminDebugOpsEnabled()` 二次拦截。
- 新增中间件时在 `routes.go` 明确挂载顺序。
